## 当前软件修复验证了什么

总线查询增加发送前 2 ms 静默间隔，常规读回重试间隔为 20/50 ms。三个纯空 RX 超时之后，允许等待 200 ms 后完整重读该反馈组：每组最多一次、每次完整抓放最多四次。初始六轴检查、夹爪单轴组、腕部单轴组都覆盖。部分坏包、线路错误、越界反馈与未到位不被当作成功恢复。

回归覆盖了：初始六个 ID 分别故障、不同动作中再次出现丢响应、同组恢复耗尽、四次总预算、MOVE 失败不重放、反馈越界与到位不符、取消/时钟异常/看门狗、初始检查期间取消、TARGET_STALE 不下发动作、规划失败清除上一任务摘要。总线与时钟在这些测试中是模拟的。

UI/自动任务回归另外检查了类别显示、颜色、刷新帧新鲜度以及任务状态。不能把“离线 PASS”解释为真实电机已经多次运行通过。复现脚本由仓库 [scripts](../scripts/) 提供，实际运行入口以仓库构建说明为准。

## 继承位流的资源与时序

当前 PS 修复使用的位流 SHA-256：

`39bb582ed3a775eed181887ef1b76f9860691f3419cbda8c44267acc5829249f`

| 资源 | 使用 / 总量 | 占用 |
|---|---:|---:|
| LUT | 33,625 / 53,200 | 63.20% |
| FF | 21,701 / 106,400 | 20.40% |
| Slice | 10,656 / 13,300 | 80.12% |
| BRAM tile | 134 / 140 | 95.71% |
| DSP | 63 / 220 | 28.64% |
| SLICEM | 3,553 / 4,350 | 81.68% |

同一硬件记录的 WNS 为 +0.235 ns、WHS 为 +0.030 ns、TNS/THS 为 0；49,646 条可路由网络全部完成，记录的路由错误数为 0。识别控制 FCLK0 为 100 MHz。资源百分比不是“整个 FPGA 已使用 95.71%”：这里主要瓶颈是 BRAM，还需要考虑布局、存储端口和时序。

这些结果来自继承的实现记录，当前软件修复未改变位流。更换 Vivado 版本、IP、RTL、约束或重新布局后，必须重新检查报告；不能把旧数字当作新构建测量值。

当前设计仍存在应披露的约束条件：相机 PCLK 使用非专用时钟引脚 W10，输入延迟预算是工程假设，不是实测传感器 tCO；部分跨时钟/异步接口依赖显式例外与同步器。因此不能仅凭正 WNS 宣称所有外设与 CDC 风险都已消除。

## 性能与准确率的边界

- 1280×720、60 Hz 是 HDMI 扫描时序；约 11.67 fps 才是当前配置的新相机画面率。最新总线修复版没有重新测量它。
- 200 ms 是识别调度目标间隔，不保证 12 目标场景每秒完成 5 次推理。
- 模型报告是筛选后 ROI 分类。旧 15 类测试集合历史上参与过开发评估；新增螺母测试场景未参与本轮选参，但分组前质量审查看过缩略图。
- 增强样本共享原场景，不能作为同样数量的独立采集图片。检测漏检、误检、姿态/坐标误差、遮挡和抓取成功率应单独统计。
- 机械臂当前参数与标定针对原机，离线 IK 可达不证明真实空间无碰撞。

## 后续验收建议

对新搭建的设备，先按 [硬件说明](HARDWARE.md) 验证供电、画面、输入和坐标。随后分别记录：固定场景新画面率；1/6/12 目标识别完成率；每类混淆矩阵；独立尺量的全场定位误差；单目标、单类、自动分拣的完整成功/失败次数及具体阶段。真实总线故障应保留错误类型和舵机 ID，不能把重试后的成功隐去，也不能通过跳过反馈检查提高表面成功率。

此仓库不公开原机串口历史和含个人路径的完整运行日志。证据摘要、公开源码和可复跑的测试用于说明已经验证的范围；没有提供的板上证据应明确记为未验证。
