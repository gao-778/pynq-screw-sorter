# ScrewSort 设计报告

## 应用与目标

系统面向桌面螺丝识别、定位与分拣，完成从相机感知到机械执行的任务链。目标平台为 PYNQ-Z2 / xc7z020clg400-1。18 个类别中，15 类螺丝支持抓取，3 类螺母支持识别与统计；同时展示最多 12 个目标。

## 设计原理与划分

PL 执行相机采集、DDR 图像访问、阈值与连通域、旋转 ROI、量化 CNN、覆盖层和 HDMI；PS 执行目标有效性、毫米坐标、运动规划、分拣和用户交互。高带宽图像路径和 CNN 位于 PL，任务组织与状态转换位于 PS。64×64 单通道 CNN 使用 1→32→96→256 通道与 255,912 个可训练参数。

裸机 C 与 PYNQ/Linux 编译同一组共享源码，只选择不同的平台适配层。共享应用提供初始化、有限工作量服务、状态、命令、取消和关闭接口。裸机主循环直接调用，PYNQ 后台线程通过 C 共享库调用；Python/Jupyter 提供调试和复现入口，不把 CNN 改到 PS 计算。模型与标定各有一份逻辑配置，数据文件和 C 参数表示逐项校验。

## 数据与接口

两种平台使用统一版的动态地址 RTL。裸机在保留 DDR 区配置灰度、预览和截图缓冲区；PYNQ 分配设备可访问的连续内存，分别向 C 绑定虚拟指针与设备地址。数据生产者在地址配置完成后才启动；关闭时停止任务和生产者，等待 AXI/DMA 排空后释放内存。旧固定地址位流不能与新 PYNQ 包装器混用。

动作使用不可变目标快照，整个动作期间门控识别；恢复需新采集场景和发布握手。自动分拣逐次重新选择目标并确认移除，通信故障终态不会隐式视为成功。Linux 调度不构成硬实时保证，关键串口服务优先于文件与界面工作。

## 实现与测量

配套 PL 的既有实现报告记录 LUT 33514/53200、FF 21991/106400、BRAM 134/140、DSP 63/220；WNS 0.015 ns、WHS 0.050 ns、TNS/THS 为 0。相同硬件供两种 PS 运行方式使用，不把它们计为两套独立资源实现。原始报告在 `build/reports/hardware/`；这组数据不是本轮公开整理重新综合实现的结果。

原统一包归档记录 18 项 Python/C API、两种目标各 23 组生产状态机、25 组串口协议/运动恢复与 10 组联合运动、32 组 OBB 坐标、裸机平台及 RTL 动态地址和事务排空检查；还包含 Linux ARM 共享库交叉编译、standalone ELF/BOOT 构建及 Vivado 工程/IP 生成记录。原状态见 [validation.json](validation.json)，本轮具体复测范围见 [publication_review_20261103.json](publication_review_20261103.json)。工程生成通过不等于本轮完整综合实现通过。
