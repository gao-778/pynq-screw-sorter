# FPGA 软硬件划分

把需求转换为可实现的模块和接口，而不是根据语言偏好决定放在 PS 或 PL。

## 输入与决策

读取算法描述、输入输出尺寸/速率、目标器件、外设和实时期限。缺少测量时把预算标为估计，记录假设和可替换参数。

1. 画出完整数据流，把采集、预处理、计算、结果发布、任务组织、执行和诊断分开。
2. 为每条边声明数据类型、布局、长度、吞吐、生产者、消费者和所有权；区分平均吞吐与最坏服务间隔。
3. 优先评估规则并行、流水和高带宽处理放 PL；动态组织、文件、交互和复杂策略放 PS。低延迟外设服务按实际期限决定，不能默认 Linux 线程满足硬实时。
4. 预算算术资源、BRAM、LUTRAM、DDR 带宽、帧缓存和握手开销。DDR 流量包括重复读写、对齐和并发主设备。
5. 比较至少一个合理基线，说明划分改变了什么成本；对已确定的用户架构只分析必要的替代方案。

## 接口契约

每个模块明确：时钟/复位域、寄存器访问属性、启动/完成/错误条件、背压、缓存责任、数据有效期、超时、取消与恢复语义。区分 CPU 虚拟地址、设备地址和总线地址位宽。

显示可以消费历史快照；运动或控制只能使用满足有效性契约的数据。界面、日志和计数不能成为关键控制链的隐含依赖。

## 输出与检查

交付模块划分表、数据流图、接口表、预算及关键取舍。将预算与综合/实现数据、端到端测量分别列示。对不同划分比较同一数据集、时钟和测量边界。

可使用的提示词：
> 根据提供的数据流、器件和期限，提出模块划分与接口契约。列出资源及带宽预算、最坏服务间隔、假设和可能失效的边界，不以语言或框架名称代替划分依据。

## 适用边界与经验来源

适用于可明确数据流和外设契约的系统。设备与测量资料不足时输出带假设的方案，不能承诺闭环时延。方法来自相机采集、硬件视觉、PS 控制和显示并发系统中，计算吞吐与外设服务期限相互独立的观察。
