# FPGA 验证与交付证据

将需求、设计变化与证据关联，不用单一成功标志替代完整工程结论。

## 证据层次

按当前工作实际需要选择：接口/算法参考、生产软件状态机、RTL 功能、综合、布局布线与时序/CDC、板级测量、从零复现。每一层说明输入、环境、观察值、判据和适用范围。

黄金参考应有独立依据；如果参考和实现共享同一错误假设，输出相同不能证明正确。对定点算法声明位宽、舍入、饱和、预处理和允许误差。把 ROI 分类、整图检测、设备到位和任务成功作为不同指标。

## 实现检查

收集实际器件、工具版本、时钟、约束覆盖、资源及最终实现时序。结合 BRAM、LUTRAM、SLICEM 站点和布局判断容量；总 LUT 余量不代表内存或布线有余量。

对 CDC 确认拓扑、接收端和例外范围：同步器首级异步例外不能覆盖后续应计时阶段；握手数据束还需相应稳定性和偏斜约束。Tcl 断言放在支持完整 Tcl 的流程脚本中，避免假定 XDC 支持任意控制语句。

显式终点的 timing query 可能返回带 False Path 标记但无 SLACK 的路径对象。检查路径属性和约束意义，不用“返回路径数非零”直接判定它仍受正常时序分析。

## 对照与交付

1. 固定基线与变更版本，记录模型/数据、工具参数、时钟及测量边界。
2. 自动采集原始报告，生成资源、吞吐、延迟和误差对照。实现工具的时序频率不等于应用实测帧率。
3. 保存源清单、哈希、构建命令和运行入口，使用独立输出目录，检查依赖是否残留在原机器。
4. 位流若因导出重写日期/时间头而字节不同，解析头部并比较器件、设计身份和完整配置 payload；不能直接忽略所有差异。成对硬件交付物应来自统一导出源。
5. 区分第三方声明、自己执行得到的结果和待测量项。报告只使用有对应证据的数据，不把未知结果填成成功。

## 大模型协作材料

记录问题、输入版本、提示词、模型建议、实际修改、结果和纠错。保留真实交互；事后归纳可以作为摘要，但不能伪装成当时的原始回答。提炼 Skill 时说明哪次失败或观察改变了方法。

## 输出与复用边界

输出证据索引、需求与证据对应表、优化对照、构建/部署说明及适用范围。优先适配不同报告解析器和黄金参考接口，而不是固定某个工程目录名或网络结构。非标准工具报告需要新解析器，不能静默把缺失字段填零。
