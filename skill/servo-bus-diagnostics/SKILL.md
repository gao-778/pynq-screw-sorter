# 半双工总线诊断

从协议和事务记录定位，不把总线失败直接解释为设备损坏、机械位置错误或软件调度问题。

## 输入与现场

读取总线协议、设备 ID、波特率、时钟、UART/FIFO 配置、收发使能电路、报文格式及实际接线。优先取得失败前冻结的记录，后续 STOP 或新事务不能覆盖原故障。

最小快照包含：事务类型、阶段、设备 ID、发送队列字节数、收到字节数、线路状态、已用时间、最大服务间隔、接收使能时间、首次读到回复的时间及解析失败原因。软件读取时间不是引脚上真实字节到达时间。

## 排查顺序

1. 区分请求未接受、发送等待/超时、方向切换、接收超时、线路错误、报文校验、位置范围与到位检查。
2. 核对发送 FIFO 空和发送移位器完成的区别，确认方向切换基于协议要求的实际发送完成条件。
3. 判断发包数、ID、长度、校验和以及分片/噪声处理；收到零字节与收到无效报文分开分析。
4. 对比服务间隔与协议预算，检查慢日志、界面、文件写入、线程锁或调度停顿是否落在关键窗口。
5. 有测量条件时用逻辑分析仪对照 TX、RX 和方向控制，验证软件记录的解释。

## 恢复规则

只读查询按设备协议允许有限重试；移动、释放、抓取等有副作用命令不能因回复失败自动重放。不要用扩大位置容差掩盖通信故障。日志格式化与文件同步避开关键事务窗口，保留有界 STOP 和取消路径。

## 输出与适用边界

给出故障分类、支持/反对各假设的证据、下一项可区分假设的观测及恢复条件。保留无法由现有记录确认的项。协议、方向电平、设备 ID 和时限均作为参数；该方法不假定所有设备需要响应 MOVE 或采用相同 UART 状态位。

经验来源：设备已经执行部分动作，但后续事务失败导致执行器停在中间位置；通信成功、物理到位和任务成功需要分别判断。
