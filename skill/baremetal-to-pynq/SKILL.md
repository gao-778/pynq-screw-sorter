# 裸机 C 到 PYNQ 分层移植

保留用户选择的计算架构，通过平台适配获得 Python/Jupyter 操作能力。是否重写算法由任务决定，不把全部代码改写为 Python 作为 PYNQ 的前提。

## 基线与接口盘点

找到实际生产入口、构建脚本、BSP、链接脚本、XSA/位流和模型契约；使用清单及内容确认版本，不能只按目录名或修改时间选择。识别历史源码和生成文件，在隔离目录改动。

列出每个直接平台依赖的所有者和 Linux 替代：MMIO、物理内存、缓存、计时、文件、中断、控制台、复位和设备驱动。

## 移植流程

1. 分离业务状态机与平台访问层。将主循环组织为初始化、有限工作量 service、状态查询、取消和关闭接口；初始化失败返回可处理错误。
2. 将固定物理内存变为 Python 所有的连续缓冲区。若 RTL 固定 DDR 地址，需要硬件地址配置能力并重新生成匹配 Overlay，不能仅改 C 指针。
3. MMIO 通过映射后的地址访问；对越界和非法区间明确失败。使用单调时钟，保持计时单位、回绕和截止期限语义。
4. 将裸机文件路径映射到 Linux 输出目录。串口、复位和中断重新确认所有权，避免同时接管 Linux 控制台或使用裸机 PS 复位命令。
5. 暴露稳定 C ABI，明确类型宽度、缓冲区容量、返回码、对象生命周期及回调线程。Python 用 ctypes/cffi 等适当桥接，文件路径和字符串编码显式处理。
6. Python 管理 Overlay、内存、命令队列和后台服务。取消请求优先于排队动作，关键事务不被可选日志和 UI 工作阻塞。
7. 关闭先停止并完成必要的取消服务，再排空硬件，最后释放缓冲区。工作线程异常也必须进入有界退出路径并保留错误信息。

## 行为保持

用同一输入和事件序列检查算法、类别映射、标定、运动目标、状态转换和取消语义。跨编译只说明编译/链接层面，运行库 ABI 与部署环境仍需对应。

迁移清单及 API 轮廓见 [references/adapter_contract.md](references/adapter_contract.md)。

## 输出与边界

交付依赖盘点、保留/变更说明、C ABI、Python 入口、匹配硬件产物和从零部署步骤。业务参数与平台能力外置；不要把某个项目的图像大小、类别数、舵机 ID 或时限写进通用适配层。

Linux 后台线程不构成硬实时保证。若测得关键协议期限无法满足，应评估把相关控制放到 PL/专用控制器或采用合适的实时方案，而不是仅扩大重试和超时。
