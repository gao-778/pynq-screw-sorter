# DMA 适配契约

## 每个设备必须确认的字段

| 类别 | 适配项 |
|---|---|
| 地址 | 地址位宽、可达内存、上位地址寄存器、设备地址转换 |
| 布局 | dtype、元素数、字节数、通道、行宽、stride、bank 跨度 |
| 缓存 | coherent 属性、CPU/设备写入方向、flush/invalidate 时机 |
| 控制 | 配置顺序、启动副作用、命令能否重复、状态清除方式 |
| 停止 | 是否接受新事务、已接受事务的排空条件、空闲/停止标志 |
| 恢复 | 超时、部分传输、软复位范围、生产者/消费者协同 |

AXI DMA 的 MM2S/S2MM、VDMA 和自定义 master 分别适配。使用目标 IP 对应版本官方文档，不把某类 IP 的 0x30/0x34 等偏移推广为 DMA 标准。

## 所有权与缓存

CPU 填充输入后，在设备读取前使数据对设备可见；设备完成输出后，在 CPU 读取前使数据对 CPU 可见。缓存同步只解决可见性，不能代替传输完成。异步任务必须持有缓冲区所有者直到设备完成访问。

跨 C/Python 的 CPU 指针使用与进程相符的指针类型；设备地址使用硬件契约对应位宽。64 位主机上不能以 uint32 保存 CPU 指针；64 位总线地址不能因旧板卡使用 32 位而截断。

## 排空判据示例

- 自定义 AXI 读 master：禁止新 AR，已挂起 AR 完成握手，已有 R 流接收到最终响应，再返回 idle。
- 写 master：禁止新写请求，已经发起的 AW/W 完整处理并收到 B 后才返回 idle；AW/W 可独立停顿。
- 流 DMA：按该 IP 的停止和复位语义确认状态；源停止发送或 TLAST 缺失时，行为由实际 IP 决定。

异常关闭返回具体设备和状态，不跳过判据。允许再次尝试有界排空；硬件不能确认停止时保留缓冲区，不把重启 Python 内核当成释放仍活动 DMA 内存的通用方法。

## 复用检查

用不同 payload 模式、非平凡 stride、不同 bank 和可配置的停顿覆盖真实数据路径；改变地址位宽和元数据分类时保持检查逻辑成立。通用性来自明确配置与适配层，不等于任意板卡无需适配。

接口参考：[PYNQ allocate](https://pynq.readthedocs.io/en/latest/pynq_libraries/allocate.html)、目标设备官方产品指南。使用时核对安装版本。
