# PYNQ DMA 与内存生命周期

以缓冲区所有权和设备协议定义生命周期。DMA API 返回或运行位清零，不自动代表设备不再访问内存。

## 输入契约

先确认设备类型、通道、地址位宽、可达内存、对齐、长度/步长、数据类型、缓存属性及启动/停止/空闲定义。AXI DMA、VDMA 和自定义 master 的寄存器及停止语义不同。

## 内存与缓存

1. 由 `pynq.allocate` 等目标环境支持的机制分配设备可访问缓冲区，并保持 Python 所有者存活。
2. 区分 CPU 虚拟指针、设备地址和偏移；给 C 传递匹配其指针/总线位宽的类型。禁止把 Linux 物理地址直接强转成 CPU 指针。
3. 校验每个设备访问区间的容量、对齐、可达性和不重叠约束；bank 跨度和 stride 计入完整区间。
4. CPU 写入、设备读取前按缓存策略 flush；设备写入、CPU 读取前 invalidate/sync。按目标版本 API 与缓冲区属性处理，不把所有平台都当作非一致性或一致性系统。
5. 启动前绑定地址，避免设备用复位默认地址发起事务。运行中更改地址需要设备明确支持的原子切换协议。

## 停止与释放

禁止新任务，停止生产者，取消或完成已有任务，按实际 IP 的协议停止通道，等待已接受的 AXI 事务和响应完成，然后释放。

“执行器停止”“推理停止”“DMA halted”“自定义 master idle”是不同证据，按设计逐项确认。超时保留仍可能被访问的缓冲区和所有者引用，输出寄存器快照；不能仅捕获异常后继续 free。

若考虑软复位，先核对该 IP 的官方语义、影响的通道与外部复位连接，再定义恢复步骤。不能把停止寄存器、全局复位或重载位流当作所有主设备通用的排空方式。

## 输出与验证

输出分配/绑定/运行/停止/排空/释放状态表、缓存责任表及诊断字段。验证数据模式和黄金结果，并覆盖地址/响应停顿、部分传输、取消、异常退出和重复会话。关闭条件按设备状态断言，不靠固定延时猜测。

经验来源：裸机固定地址不能直接作为 Linux 内存所有权，以及存在未返回事务时过早释放缓冲区的风险。适用于有明确内存与停止协议的设备；跨板卡需重新取得地址与一致性能力，不能保留某块板的 DDR 上限。
